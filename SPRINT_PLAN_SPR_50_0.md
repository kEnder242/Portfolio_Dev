## 3. Speculation on What Actually Happened During the `intercom.html` Crash

Based on kernel systemd records and local architecture analysis:

```
[Browser Client: intercom.html]
         │
         │ (1. Opens WebSocket connection)
         ▼
[AcmeLab / lab-attendant.service (Port 8765)]
         │
         │ (2. Triggers EarNode PCM stream / LLM context load)
         ▼
[z87-Linux RAM / Swap Space] ──▶ Hits System RAM Ceiling ──▶ [Kernel OOM Killer / System Hard Lockup]
```

### The Mechanism of Failure:
1. **WebSocket Connection Trigger**: When `intercom.html` opened in the browser, `intercom_v2.js` initiated a WebSocket connection to `lab-attendant` on port 8765.
2. **Sensory Node Memory Spike**: The connection triggered backend audio buffer allocations (EarNode PCM 16kHz stream) alongside active local vLLM KV-cache allocations.
3. **RAM & Swap Thrashing**: `z87-Linux` system memory hit 100% utilization. Because host swap space was being actively thrashed, kernel I/O blocked all userland processes—including `sshd` and `code-tunnel`—causing the system to appear completely frozen/crashed.
4. **OpenCode Had No Role**: OpenCode was idle/inactive. The memory pressure was entirely generated by the interaction between the browser WebSocket client, `lab-attendant`, and local LLM/audio buffer memory footprints.
