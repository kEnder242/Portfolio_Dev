## 🔍 Architectural Friction Report & The Self-Contained Spine Design

### 1. ⚖️ The Tradeoff Audit: Redundant (Self-Contained) vs. Sparse (Micro-Files)

| Dimension | Sparse Micro-Files (`bones/<node_id>.json`) | Redundant Self-Contained (`PAPER-xxx_vN.json`) |
| :--- | :--- | :--- |
| **Verification & Invariants** | **High Friction:** Requires assembling the tree in-memory before running CP-1 / CP-5 / CP-7. | **Zero Friction:** The file *is* the verified artifact. One-pass AST validation. |
| **Offline Portability & Tooling** | **Poor:** An external tool or static HTML site cannot render a paper without a reconstitution compiler. | **Superb:** Clean vanilla JSON/Markdown readable by `papers.html`, Python, or human text editors. |
| **File-System Overhead** | **High Risk:** Hundreds of 1KB files, directory clutter, and race conditions during multi-node edits (Oracle `WIS-502`). | **Clean:** 1 file per certified major version (`v1`, `v2_recruiter`, `v3_executive`). |
| **Decomposition Complexity** | Full AST decomposition into micro-shards. | **Simple:** Parsing, citation tagging, and diff mapping between complete versions. |

> **Verdict:** **Self-Contained Full Text wins overwhelmingly.**  
> Redundancy here is not waste—it is **verifiable isolation**. Each version of a document is an immutable historical milestone.

---

### 2. 🏛️ Where Does That Leave the Spine? (No `bones/` folder needed!)

By keeping full-text version files, we eliminate the need for a separate `bones/` directory on disk. 

The **Spine (`PAPER-<id>_spine.json`)** becomes the **Master Version Manifest & Document-DNA Archive**:

```
Portfolio_Dev/field_notes/data/papers/
├── PAPER-RESUME_spine.json                     # Master Version Topology & Document DNA Archive
├── PAPER-RESUME_v1.json                        # Baseline Milestone (Origin Text + Raw Anchors)
├── PAPER-RESUME_v2_farah_sharghi_recruiter.json # Stylistic Milestone (ATS / Recruiter Projection)
└── PAPER-RESUME_v3_executive.json              # Stylistic Milestone (Executive Brief)
```

#### What Lives Inside `PAPER-<id>_spine.json`:
1. **Version Index & Lineage:** `["v1", "v2_recruiter", "v3_executive"]` with parent pointers and timestamped rationale.
2. **Topological Coordinate Map:** The section $\rightarrow$ block $\rightarrow$ node mapping across versions (tracking which nodes were `MOVED`, `REWORDED`, or `ADDED`).
3. **Local Bone Collection (Document-Specific DNA):** An offline snapshot of all DNA cards and citations generated by or tied specifically to this document.

### 3. 🧬 Document-Specific DNA & The Promotion Lifecycle Gate

```
┌─────────────────────────────────────────────────────────┐
│              DOCUMENT-SCOPED DNA (Local)                │
│  ID Stamp: [DOC-RESUME-001], [DOC-JITC-012]             │
│  Stored In: PAPER-<id>_spine.json -> "document_dna": [] │
│  Scope: Transient, local to this document's iterations. │
└────────────────────────────┬────────────────────────────┘
                             │
                  Promotion Gate (BKM-060)
         (When insight exceeds 0.85 global utility)
                             ▼
┌─────────────────────────────────────────────────────────┐
│                 LAB-WIDE DNA (Global)                   │
│  ID Stamp: [WIS-501], [INS-041], [BKM-073]              │
│  Stored In: wisdom_data.json -> ChromaDB :8001          │
│  Scope: Permanent, searchable by all swarm agents.      │
└─────────────────────────────────────────────────────────┘
```

1. **Document-Scoped DNA Stamp:** `DOC-<paper_slug>-<idx>` (e.g., `DOC-RESUME-001`, `DOC-SEMANTIC-004`).
   - Stored directly inside `PAPER-<paper_id>_spine.json`.
   - Never pollutes the global CLaRa-DNA collection until promoted.
2. **The Promotion Gate (`BKM-060`):**
   - If a document-specific insight or war story has broad, lab-wide architectural value, a human or agent can trigger `promote_to_lab_dna(doc_dna_id)`.
   - It gets minted as a permanent `WIS-xxx` or `INS-xxx`, added to `wisdom_data.json`, and synced to ChromaDB `:8001`.

## 🎯 Architectural Mandates (BKM-073 / BKM-060 / BKM-070 / BKM-049 / BKM-024)
1. **SELF-CONTAINED MILESTONE INVARIANT (BKM-073 / INS-041):** Every document version is stored as a 100% self-contained, human-readable JSON artifact (`PAPER-<id>_<version>.json`). No sparse micro-files or runtime reconstitution engines.
2. **SPINE AS VERSION MANIFEST & DNA VAULT (FEAT-626):** `PAPER-<id>_spine.json` acts as the single authoritative index for version lineage, topological node mapping, and document-scoped DNA collections (`document_dna: []`).
3. **DOCUMENT DNA PROMOTION GATE (FEAT-628 / BKM-060):** Document-scoped DNA (`DOC-<id>-<idx>`) is strictly quarantined inside the spine until explicitly promoted to global lab DNA (`WIS-xxx` / `INS-xxx`) via certified utility evaluation.
4. **LENS AS LITMUS TEST (FEAT-585 / BKM-070):** The active Lens determines node recommendations. Recommending an older revision requires explicit lens-specific justification. Quality inversions are flagged unconditionally as warnings.
5. **MICRO-SCALE SANDBOX BOUNDARY (FEAT-627):** `projection_studio.html` is strictly an isolated single-node R&D proving ground for LLM editorial dialectics, revision blending, and "Reason Why" validations before stamping updates into document files.
6. **TRI-LOOP DELEGATION MANDATE (BKM-049):** Every story declares an assigned owner (`[SWARM:LOCAL]`, `[SWARM:CLOUD]`, or `[AGY:PRIMARY]`). Local stories execute via single-shot `delegate.py` with the Psychological Safety Contract (`FEAT-625`) and up to 3 diagnostic remediation rounds before cloud escalation.
